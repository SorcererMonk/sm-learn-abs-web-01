## HTML email: a separate platform

### Rendering engines

**Outlook for Windows** (classic versions render with Word's engine; the new Outlook is web-based), **Gmail** (strips `<style>` in some contexts, rewrites classes, clips messages over ~102 KB), **Apple Mail** (WebKit, the most capable), Yahoo, Samsung, and dark-mode behaviour that differs in each.

### Techniques

**Table-based layouts** with `role="presentation"`, **inline styles** (tools inline them for you), a ~600px maximum width, hybrid ("spongy") fluid layouts, **`<!--[if mso]>` conditional comments**, **VML** for Outlook background images and bulletproof buttons, web-safe font stacks (web fonts as enhancement), images with `alt` and dimensions (many clients block images), **preheader** text, and `bgcolor` attributes.

### Dark mode, accessibility and tooling

Dark mode: the `color-scheme` meta and `prefers-color-scheme` where supported; some clients **force-invert** colours, so use transparent PNG logos with an outline. Accessibility: `lang`, `role="presentation"` on layout tables, real text (not images of text), contrast, semantic headings, clear link text. Tooling: **MJML**, **Maizzle**, React Email, Foundation for Emails; test with Litmus or Email on Acid; send a plain-text alternative; mind deliverability.

## Print CSS

`@media print`: hide navigation and interactive chrome, show link URLs (`a[href]::after { content: " (" attr(href) ")" }`), black on white, no backgrounds. **`@page`** sets `size` and `margin`, with `:first`, `:left` and `:right` pages and margin boxes for running headers and footers (partially supported). **Fragmentation**: `break-before`, `break-after: avoid` on headings, `break-inside: avoid` on figures, `orphans` and `widows`. Tables repeat their `<thead>`. `print-color-adjust: exact` when backgrounds must print. Test with DevTools' print emulation (Rendering → Emulate CSS media type: print) and real printers. This site has a print stylesheet: print any lesson.

## Paged media and PDF generation

HTML → PDF with **headless Chromium** (Puppeteer/Playwright `page.pdf()`), **WeasyPrint**, **Prince** or Vivliostyle. The **Paged.js** polyfill adds running headers, page counters (`counter(page)`), footnotes and cross-references to browsers. Build invoices, résumés, reports and books from HTML and CSS.

```css
/* An invoice's page model (Paged.js, WeasyPrint and Prince support margin boxes) */
@page {
  size: A4;
  margin: 20mm 18mm 25mm;
  @bottom-left   { content: "Invoice INV-2026-042 · Studio Rao"; font: 8pt system-ui; }
  @bottom-right  { content: "Page " counter(page) " of " counter(pages); font: 8pt system-ui; }
}
@page :first { @bottom-left { content: none; } }
thead { display: table-header-group; }   /* repeat the line-item header on page 2 */
tr, .totals { break-inside: avoid; }
```

```ts
// Render it to PDF with Playwright (Chromium)
import { chromium } from 'playwright';
const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto('http://localhost:4321/invoice/042/', { waitUntil: 'networkidle' });
await page.pdf({ path: 'invoice-042.pdf', format: 'A4', printBackground: true, preferCSSPageSize: true });
await browser.close();
```

## Images generated from HTML/CSS

**Open Graph images** generated from templates: **Satori** (HTML/CSS → SVG, then resvg → PNG; supports a flexbox subset) or headless browser screenshots (full CSS, slower). Social cards, certificates, badges. Design within each renderer's constraints.

```tsx
// Satori: a 1200×630 OG image from JSX with inline flexbox styles
import satori from 'satori';
import { Resvg } from '@resvg/resvg-js';

const svg = await satori(
  <div style={{ display: 'flex', flexDirection: 'column', justifyContent: 'space-between',
                width: '100%', height: '100%', padding: 64, background: '#1d1a19', color: 'white' }}>
    <div style={{ fontSize: 28, color: '#fdba74' }}>Foundations · Part 23</div>
    <div style={{ fontSize: 72, fontWeight: 700, lineHeight: 1.05 }}>HTML & CSS beyond the screen</div>
  </div>,
  { width: 1200, height: 630, fonts: [{ name: 'Fraunces', data: fontBuffer, weight: 700 }] },
);
const png = new Resvg(svg).render().asPng();
```

<Try task="Sketch an OG template for this site's lessons within Satori's limits (flexbox only, no grid, inline styles). Which parts of the lesson page design can't be reproduced?">
  Title, part number, tier chip and brand colours all work with flex columns and rows. What doesn't: CSS grid layouts, `::before`/`::after` decorations, most filters and blend modes, and variable-font axes beyond weight. Replace decorations with real elements or an SVG background image.
</Try>

## Reader modes, RSS readers and syndication

Safari Reader, Firefox Reader View and feed readers extract content using **semantic markup**: `<article>`, `<h1>`, `<time>`, `<figure>`, bylines, and a clean main content region. If your page falls apart in reader mode, your HTML probably relies on `<div>`s and CSS for meaning: it's a free test of markup quality.

<Try task="Open this lesson in Firefox Reader View or Safari Reader. What survived, what disappeared, and what does that tell you about the markup?">
  Headings, paragraphs, code blocks, tables and lists survive because they're real elements in a single `<main>` with an `<article>`-like structure. Interactive demos and playgrounds disappear (they're decoration from the reader's point of view), which is fine because the explanations around them carry the meaning. If a page's reader view shows only a fragment, its main content probably isn't marked up as such.
</Try>

## Kiosk, TV and large-screen interfaces

**Spatial (D-pad) navigation** (arrow keys move focus in two dimensions), focus styles **visible at a distance**, 10-foot typography (large sizes, high contrast), **overscan safe areas** (keep content inside ~5% margins), and low-power hardware (few effects, no huge DOMs).
