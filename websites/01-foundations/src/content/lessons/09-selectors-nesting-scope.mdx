## Basic selectors and attribute selectors

Type (`p`), class (`.card`), ID (`#main`), universal (`*`), and **attribute selectors**: `[attr]` (present), `[attr="v"]` (exact), `[attr~="v"]` (word in a space list), `[attr|="en"]` (`en` or `en-…`), `[attr^="https"]` (starts), `[attr$=".pdf"]` (ends), `[attr*="shop"]` (contains), with `i` (case-insensitive) or `s` flags. Attribute selectors on **`aria-*` and `data-*`** are an excellent way to style state: `[aria-expanded="true"]`, `[data-variant="primary"]`.

## Combinators

Descendant (space), child (`>`), next-sibling (`+`), subsequent-sibling (`~`), and the column combinator (`||`, rare). Engines match selectors **right to left**: `.sidebar ul li a` first finds every `a`, then walks up. That's why the rightmost part (the *key selector*) matters for performance in huge DOMs, though it rarely matters in practice.

## Structural pseudo-classes

`:root`, `:empty`, `:first-child`/`:last-child`/`:only-child`, **`:nth-child(An+B [of S])`** (the `of S` filter counts only matching siblings), `:nth-last-child`, and the `:nth-of-type` family. **Quantity queries** style a group by how many items it has: `li:first-child:nth-last-child(n+5)` means "the first item of a list with five or more".

## Logical pseudo-classes: `:is()`, `:where()`, `:not()`, `:has()`

`:is()` groups with a *forgiving* list (one invalid selector doesn't kill the rest) and takes the **highest** specificity of its arguments. **`:where()`** does the same with **zero** specificity. `:not()` accepts complex selectors now. **`:has()`** is the "parent selector" and much more: relational (`.card:has(img)`), form-level (`form:has(:user-invalid)`), sibling lookahead (`h2:has(+ p)`), and page state (`body:has(dialog[open])` to lock scrolling). Its caveat is invalidation cost in huge, frequently mutating DOMs.

## Pseudo-elements and the Custom Highlight API

`::before`/`::after` need `content` and don't work on replaced elements (`<img>`, `<input>`). Also `::marker`, `::placeholder`, `::selection`, `::first-line`, `::first-letter` (with **`initial-letter`** for real drop caps), `::backdrop`, `::file-selector-button`, `::cue`, `::details-content`, `::picker()`, `::scroll-marker`/`::scroll-button()` **[Frontier]**, `::target-text` (text fragments), `::spelling-error`/`::grammar-error`, and the `::view-transition-*` tree (Part 17). The **Custom Highlight API** styles arbitrary text ranges (search matches, syntax colouring) through **`::highlight(name)`** without wrapping anything in spans.

## Shadow DOM selectors

Inside a shadow root: **`:host`** styles the custom element itself, `:host(.active)` when the host matches, `:host-context()` (not universally supported: avoid), and **`::slotted()`** for *top-level* slotted nodes only. From outside, **`::part(name)`** styles elements the component explicitly exposes with `part="name"`: a deliberate styling API (Part 20).

## Native CSS nesting

Rules can nest: `.card { & h2 { … } }`, or without `&` for descendants (`.card { h2 { … } }`). `&` means "the parent selector" and can go anywhere (`.theme-dark &`, `&:hover`, `&.is-active`). At-rules nest too (`@media` inside a rule). Nested selectors desugar to **`:is(parent)`**, so they take the parent list's *highest* specificity: a surprise when that list contains an ID. Keep nesting to two or three levels; deeper nesting hides specificity and couples markup to CSS.

```css
.card {
  padding: 1rem;
  & h2 { font-size: 1.25rem; }            /* .card h2 */
  &:hover { border-color: currentColor; }  /* .card:hover */
  .theme-dark & { background: #1d1a19; }   /* .theme-dark .card */
  @media (width >= 40rem) { padding: 2rem; }
}

/* The trap: this becomes :is(#hero, .card) h2, specificity (1,0,1) for BOTH */
#hero, .card {
  & h2 { color: crimson; }
}
.card h2 { color: seagreen; }              /* (0,1,1): loses, even though it's later */
```

## `@scope`

`@scope (.card) { img { … } }` applies styles only inside `.card`, and **scope proximity** is a cascade step: when two scoped rules tie, the one whose root is *nearer* wins (so a light card inside a dark section works). The **donut scope** `@scope (.card) to (.card__content)` stops at a lower boundary, so styles don't leak into slotted or user-authored content. `:scope` targets the root. A `<style>` element's `@scope { }` with no selector scopes to its parent element. It's a native alternative to BEM naming or CSS Modules.

## Selector performance in practice

Selectors are rarely the bottleneck compared with layout and paint. The real costs are **huge DOMs**, **invalidation** from `:has()` and sibling combinators on subtrees that change often, and universal-selector-heavy rules re-evaluated on every mutation. Measure before optimising: DevTools → Performance → enable **selector stats** to see which selectors cost the most time during style recalculation.

```css
/* Fine: scoped, the subject is specific */
.cart:has(.item--error) .checkout { opacity: .5; }

/* Risky in a 10,000-node live-updating table: every mutation re-checks the whole body */
body:has(td:hover) * { transition: none; }
```

<Try task="Open DevTools on a large page (a web mail client or a social feed), record a Performance trace while scrolling, and find the longest 'Recalculate Style' event. How many elements did it affect?">
  Look at the "Elements affected" count and, with selector stats enabled, the top selectors by elapsed time. Typically the fix is fewer elements (virtualisation, `content-visibility: auto`), a narrower `:has()` subject, or avoiding class changes on `<body>` that invalidate the whole tree, rather than rewriting selectors.
