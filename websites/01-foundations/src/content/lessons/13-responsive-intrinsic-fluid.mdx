## The philosophy arc: from fixed to intrinsic

**Fixed-width** (960px and pray) → **fluid** (percentages) → **responsive** (Ethan Marcotte, 2010: fluid grids, flexible images, media queries) → **mobile-first** → **intrinsic web design** (Jen Simmons: content-driven sizing with grid, flex, `minmax()`, `min()`/`max()`) → **component-responsive** (container queries). The modern goal: **layouts that respond to the space they're given, not the device they're on**.

## Media queries, properly

Use the **range syntax** (`@media (width >= 48rem)`), write breakpoints in **`em`/`rem`** so they respect the user's font size, set them **by content** (where the design breaks), and layer **mobile-first** with `min-width`. Width is the least interesting feature. The ones that matter: `hover`, `pointer`, `any-hover`, `any-pointer`, `orientation`, `resolution`, **`prefers-color-scheme`**, **`prefers-reduced-motion`**, `prefers-contrast`, `prefers-reduced-transparency`, `prefers-reduced-data` **[Frontier]**, **`forced-colors`**, `dynamic-range`, `color-gamut`, `display-mode` (installed PWAs), `scripting` and `print`.

## Container queries

Make an element a query container with **`container-type: inline-size`** (size containment on the inline axis) or `size`, name it with `container-name` (or the `container` shorthand), and query it: **`@container card (width > 30rem)`**. **Container query units** (`cqi`, `cqb`…) size things relative to the container: fluid type inside components. The side effect of containment: a size container can't size itself from its children on that axis. Components designed this way adapt wherever they're placed.

## Style queries and scroll-state queries

**Style queries** test a container's custom property: `@container style(--variant: compact)` lets one variable on a parent drive a whole subtree's styling. **Scroll-state queries** **[Frontier]** style things by scroll state: `@container scroll-state(stuck: top)` (a sticky header that has stuck), `snapped` and `scrollable`.

## Fluid typography and space

`clamp(min, preferred, max)` with a preferred value that **mixes `rem` and `vw`** (or `vi`, or `cqi` inside components) grows smoothly between two viewport widths and still scales with user zoom and font-size settings (WCAG 1.4.4). **Pure `vw` type fails**: it ignores the user's font size. **Utopia**-style scales generate every type step and space token from two viewports, two base sizes and two ratios. Fluid spacing keeps rhythm proportional; watch **line length** as type grows. This site's tokens are generated this way.

## Viewport realities on mobile

`100vh` on mobile is the height with the address bar *retracted*, so a "full-screen" hero is cut off. Use **`svh`** (small: bar visible, stable), **`lvh`** (large), or **`dvh`** (dynamic: tracks the bar, may cause jumps). Draw into notches with `viewport-fit=cover` plus `env(safe-area-inset-*)` padding. The on-screen keyboard: `interactive-widget=resizes-content` in the viewport meta, the **VirtualKeyboard API**, and the **visual viewport** API. `-webkit-text-size-adjust: none` stops landscape text inflation. The 300ms tap delay disappears with a correct viewport meta.

## Intrinsic layout primitives

From *Every Layout* (Heydon Pickering and Andy Bell): small CSS algorithms that compose into almost any layout without media queries. **Stack** (vertical rhythm with `* + *`), **Box** (padding and border), **Center** (max-width + auto margins, optionally intrinsic), **Cluster** (wrapping flex with gap), **Sidebar**, **Switcher**, **Cover** (vertically centred principal element between header and footer), **Grid** (`auto-fit` + `minmax(min())`), **Frame** (aspect-ratio crop), **Reel** (horizontal scroller), **Imposter** (centred overlay) and **Icon** (inline icons sized with `1cap`/`1ex`). This site's `layout.css` implements all twelve.

## Responsive typography, images and components together

Responsiveness is more than layout: **art direction** for images (Part 4), different **content priorities** per size (reorder or progressively disclose, but don't hide content from mobile users), **touch vs pointer affordances** (`@media (pointer: coarse)` for larger targets), and hover-dependent UI with non-hover fallbacks.

## `zoom`, and testing at 200% and 400%

The **`zoom`** property is now standardised **[Frontier]**: it scales an element *and* its layout (unlike `transform: scale`), and container queries see the zoomed size. Distinguish **browser zoom** (changes the CSS pixel size, so media queries respond), **pinch zoom** (magnifies the visual viewport only) and **text-only zoom** (changes the root font size, so only `rem`/`em` respond). WCAG requires text resizing to 200% and **reflow at 320 CSS px** (the width of a 1280px screen at 400%).

## Testing responsive work

DevTools device mode is a starting point, not a device. Also use Firefox's and Safari's responsive design modes, **real devices** (at least one small Android, one iPhone, one tablet), **resize continuously** rather than jumping between presets (breakpoints hide between presets), and visual regression snapshots at a range of widths.

<Try task="Take any page you've built and drag the window slowly from 1920px down to 280px. Write down every width where something looks wrong, then fix each with intrinsic sizing before reaching for a media query.">
  Typical finds: a nav that overflows just before its breakpoint (use a Cluster or `flex-wrap`), a card grid that jumps from 3 to 1 column (use `auto-fit` + `minmax`), a headline that overflows at 320px (use fluid `clamp()` type and `overflow-wrap: break-word`), and a fixed-width form (use `max-inline-size` instead of `width`). Keep only the media queries that change *design intent*, not those that patch overflow.
</Try>
