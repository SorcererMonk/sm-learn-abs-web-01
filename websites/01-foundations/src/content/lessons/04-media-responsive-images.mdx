## `<img>` properly

- **`alt`** is the text alternative: describe the image's *function and content in context*. Decorative images get `alt=""` (present but empty, so screen readers skip them). Never the filename. Complex images (charts, diagrams) get a short alt plus a longer description nearby.
- **`width` and `height`** attributes let the browser compute the **aspect ratio** and reserve space before the file arrives: no layout shift. CSS can still make the image fluid (`max-width: 100%; height: auto`).
- **`loading="lazy"`** below the fold only, and **never on the LCP image**. `decoding="async"` lets decoding happen off the critical path. **`fetchpriority="high"`** on the hero. Plus `referrerpolicy` and `crossorigin` when you need them.

## Responsive images: `srcset`, `sizes` and `<picture>`

**Resolution switching** with `x` descriptors serves a fixed-size image crisply on dense screens: `srcset="logo.png 1x, logo@2x.png 2x"`. **Width switching** lists real file widths with `w` descriptors and tells the browser the layout width with **`sizes`**. The browser multiplies the slot width by the device pixel ratio and picks the smallest file that covers it. `sizes="auto"` lets lazy images use their laid-out width **[Frontier]**.

**`<picture>`** is for two other jobs: **art direction** (different crops per breakpoint via `media`) and **format switching** (`type="image/avif"` → WebP → JPEG). The browser uses the first matching `<source>`; the `<img>` inside is required and carries `alt`, dimensions and loading hints.

<ResponsiveImagePicker />

```html
<picture>
  <source media="(min-width: 48rem)" type="image/avif"
          srcset="hero-wide-1200.avif 1200w, hero-wide-2400.avif 2400w"
          sizes="100vw" width="2400" height="1000">
  <source type="image/avif" srcset="hero-sq-600.avif 600w, hero-sq-1200.avif 1200w" sizes="100vw">
  <source type="image/webp" srcset="hero-sq-600.webp 600w, hero-sq-1200.webp 1200w" sizes="100vw">
  <img src="hero-sq-1200.jpg" width="1200" height="1200" alt="Rower on a misty lake at dawn"
       fetchpriority="high" decoding="async">
</picture>
```

  `sizes="(min-width: 72rem) 22rem, (min-width: 40rem) 50vw, 100vw"`. Subtract gutters if they are large: `calc(50vw - 2rem)`. Media conditions are tested in order, so the widest breakpoint comes first.

## Image formats and when to use them

| Format | Use it for | Notes |
| --- | --- | --- |
| **AVIF** | Photos and illustrations, first choice | Best compression; slower to encode; supported everywhere modern |
| **WebP** | Universal fallback | Lossy and lossless, transparency |
| **JPEG** | The last fallback for photos | Use progressive encoding and ~4:2:0 chroma subsampling |
| **PNG** | Screenshots, lossless, transparency | Large for photos |
| **SVG** | Icons, logos, illustrations, charts | Vector, styleable (Part 5) |
| **GIF** | Nothing | Replace animations with muted looping video |
| **JPEG XL** | Watch the support tables | Excellent format, patchy support |

Quality is a design decision: find the lowest setting where you can't see artefacts at 1× and 2×, per image type. Generate variants in a **pipeline** (a build step with sharp or an image CDN), never by hand.

<Try task="Pick a format for: a product photo, a company logo, a screenshot of code, an animated loading hint, and a 3-second looping product demo.">
  Product photo: AVIF with WebP/JPEG fallbacks. Logo: SVG. Code screenshot: PNG or lossless WebP (or better, real text in `<pre>`). Loading hint: CSS or SVG animation. Product demo: a muted, looping, `playsinline` MP4/WebM video with a poster, never a GIF.
</Try>

## CSS images, object-fit and placeholders

**Content images go in HTML** with `alt`; decoration goes in CSS (`background-image`, `image-set()` for density and format). For images inside fixed boxes, `object-fit: cover` crops to fill and `contain` letterboxes; **`object-position`** moves the focal point. `aspect-ratio` gives any box a shape before its content loads. Placeholders: a dominant colour background, a blurred low-quality image (LQIP, BlurHash, ThumbHash) that fades out, and `content-visibility: auto` to skip rendering off-screen sections.

## Video and audio

`<video>` and `<audio>` with `controls` give accessible native players. **`autoplay` only works with `muted`** (and needs `playsinline` on iOS). Also `loop`, `poster` (the still before playback), and `preload` (`none`, `metadata`, `auto`). List several `<source>` formats (MP4/H.264 for reach, WebM/VP9 or AV1 for size); the first playable one wins. **`<track>`** adds WebVTT captions, subtitles, descriptions or chapters; `::cue` styles them.

A **GIF replacement** is a muted, looping, `playsinline` video: often 10× smaller. **Background video** needs a pause control (WCAG 2.2.2 for anything moving over 5 seconds), should stop under `prefers-reduced-motion`, and costs data. Adaptive streaming (HLS/DASH) is a library concern.

```html
<video controls preload="metadata" poster="/media/tour-poster.jpg" width="1280" height="720">
  <source src="/media/tour.av1.webm" type="video/webm; codecs=av01.0.05M.08">
  <source src="/media/tour.mp4" type="video/mp4">
  <track kind="captions" src="/media/tour.en.vtt" srclang="en" label="English" default>
  <track kind="chapters" src="/media/tour.chapters.vtt" srclang="en">
  <a href="/media/tour.mp4">Download the tour video (MP4, 12 MB)</a>
</video>

<!-- A GIF, done right -->
<video autoplay muted loop playsinline width="600" height="400" aria-label="Dragging a card between columns">
  <source src="/media/drag-demo.webm" type="video/webm">
  <source src="/media/drag-demo.mp4" type="video/mp4">
</video>
```

<Try task="Write the markup for a background hero video that respects reduced motion and has a visible pause button. Where does the pause state live?">

## Media accessibility

Prerecorded video needs **captions** for its audio (WCAG 1.2.2); captions include meaningful sounds, not only dialogue. Offer a **transcript** (it also helps search and skimming) and **audio description** where visuals carry information. **Never autoplay audio.** New pseudo-classes let CSS style media state: `:playing`, `:paused`, `:muted`, `:buffering`, `:seeking` **[Frontier]**.

```text
WEBVTT

00:00:00.500 --> 00:00:03.000
Welcome to the studio.

00:00:03.200 --> 00:00:05.500
[kettle whistles]

00:00:05.800 --> 00:00:09.000 line:85%
<v Asha>We start every project with a paper sketch.
```

<Try task="Write three cues of WebVTT captions for a 10-second clip where a presenter speaks, a phone rings, and a second person answers off-screen.">
  `WEBVTT`, then `00:00:00.000 --> 00:00:03.500` / `<v Presenter>Let's look at the numbers.`; `00:00:03.600 --> 00:00:05.000` / `[phone rings]`; `00:00:05.200 --> 00:00:08.000` / `<v Sam>(off-screen) I'll get it!`. Identify speakers when they aren't visible, and caption the sound because it changes the scene.
</Try>

## `<iframe>`: sandbox, permissions and facades

Every iframe needs a **`title`** (its accessible name). `loading="lazy"` defers off-screen frames. **`sandbox`** starts from zero permissions and adds tokens: `allow-scripts`, `allow-forms`, `allow-popups`, `allow-same-origin`… Never combine `allow-scripts` with `allow-same-origin` for same-origin content: the frame can remove its own sandbox. `allow` is the frame's Permissions Policy (`camera`, `fullscreen`, `clipboard-write`). `srcdoc` inlines the document; `aspect-ratio` makes embeds responsive.

A **facade** shows a lightweight static preview of a heavy embed (YouTube, maps, chat widgets) and loads the real thing only on click, which saves hundreds of kilobytes of third-party JavaScript on every visit. (The playgrounds on this site are sandboxed `srcdoc` iframes: `allow-scripts` only.)

## Other embeds: MathML, image maps and legacy elements

`<object>` and `<embed>` are legacy. `<map>`/`<area>` image maps are rare but accessible when each `<area>` has `alt` and an `href`. `<canvas>` is Part 5. **MathML Core** now renders in every engine: write real equations as markup (accessible and zoomable) instead of images. `<portal>` and `<fencedframe>` are frontier curiosities.

## Favicons and app icons

The minimal set that matters: an **SVG favicon** (it can contain a `prefers-color-scheme` media query so it adapts to dark tabs), a 32px PNG or `.ico` fallback, a 180×180 **`apple-touch-icon`**, and in the web app manifest a 192 and a 512 icon plus a **maskable** icon with safe-zone padding (Part 6).

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">
```

```xml
<!-- icon.svg: adapts to the tab's colour scheme -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <style>
    circle { fill: #c2410c; }
    @media (prefers-color-scheme: dark) { circle { fill: #fdba74; } }
  </style>
  <circle cx="16" cy="16" r="14"/>
</svg>
```
