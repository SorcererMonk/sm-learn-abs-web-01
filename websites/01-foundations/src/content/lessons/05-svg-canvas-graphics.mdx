## SVG as a language: coordinates, viewBox and preserveAspectRatio

SVG is an XML vocabulary you can write straight into HTML. It draws in **user units** on an infinite plane. **`viewBox="min-x min-y width height"`** chooses which rectangle of that plane you see (the camera); **`width`/`height`** set the size of the box on the page (the viewport). **`preserveAspectRatio`** decides what happens when their shapes differ: `meet` fits the whole view and letterboxes, `slice` fills the box and crops, `none` stretches, and the `xMin`/`xMid`/`xMax` + `YMin`/`YMid`/`YMax` alignment picks which part stays.

## Shapes and paths

`<rect>`, `<circle>`, `<ellipse>`, `<line>`, `<polyline>` and `<polygon>` cover simple shapes; everything else is **`<path d>`**. Its commands: **M** move, **L** line, **H**/**V** horizontal/vertical line, **C** cubic Bézier (two control points), **S** smooth cubic, **Q** quadratic, **T** smooth quadratic, **A** elliptical arc, **Z** close. Uppercase is absolute, lowercase relative to the current point. Read one icon path by hand and icons stop being black boxes.

## Painting: fill, stroke, gradients and markers

`fill` and `stroke` paint shapes; `stroke-width`, `stroke-linecap` (`butt`, `round`, `square`) and `stroke-linejoin` shape the outline. **`stroke-dasharray` + `stroke-dashoffset`** create dashes, and animating the offset from the path length to 0 is the famous "line drawing" effect. `vector-effect: non-scaling-stroke` keeps strokes constant when the SVG scales; `paint-order: stroke` puts the stroke behind the fill (great for outlined text); `fill-rule` (`nonzero`/`evenodd`) decides holes. Gradients (`<linearGradient>`, `<radialGradient>`), `<pattern>` and `<marker>` (arrowheads) live in `<defs>`. `opacity` fades the whole element; `fill-opacity` only the fill.

## Structure and reuse: groups, symbols, clipping and masks

`<g>` groups and transforms; `<defs>` holds things that aren't drawn until referenced. **`<symbol>` + `<use href="#id">`** is the icon-sprite pattern: define once, stamp anywhere, each copy can have its own size and colour. `<clipPath>` cuts with a hard edge; **`<mask>`** uses luminance (white shows, black hides, grey is partial) so it can fade. `<foreignObject>` embeds HTML inside SVG.

## SVG filters

Filter primitives chain like a node graph: **`feGaussianBlur`**, **`feColorMatrix`** (desaturate, tint, alpha tricks), **`feTurbulence`** (Perlin noise) with **`feDisplacementMap`** (liquid, torn-paper and glitch distortions), `feComposite`, `feMorphology` (thicken/thin), `feBlend` and `feDropShadow`. Set the filter region (`x`, `y`, `width`, `height`) so blurs aren't clipped. CSS can use them: `filter: url(#grain)`. This is where most "how did they do that texture" effects come from.

## SVG text and text on a path

`<text>` places text at a point (`x`, `y`, `text-anchor`, `dominant-baseline`); `<tspan>` styles runs; **`<textPath href>`** flows text along any path. SVG text stays selectable, searchable and accessible, but it doesn't wrap, so paragraphs belong in HTML.

## Styling and theming SVG with CSS

Presentation attributes (`fill="red"`) have **zero specificity**, so any CSS rule beats them. **`currentColor`** makes icons inherit the text colour, so one icon works on any background and in dark mode. Custom properties cross into **inline** SVG (and into `<use>` instances by inheritance), but not into `<img src="icon.svg">`, which is a separate document. The shadow tree of `<use>` can't be selected from outside; style it through inherited properties.

## Ways to include SVG

| Method | Styleable from page | Cached | Scriptable | Best for |
| --- | --- | --- | --- | --- |
| Inline `<svg>` | Yes | No (part of HTML) | Yes | Icons that inherit colour, animated or interactive graphics, charts |
| `<img src>` | No | Yes | No (safe) | Logos, illustrations, user-uploaded SVG |
| CSS `background-image` | No | Yes | No | Decorative patterns |
| CSS `mask-image` + `background-color` | Colour only | Yes | No | Single-colour icons from a file, coloured by CSS |
| `<symbol>` sprite + `<use>` | Inherited props | If external sprite file | Partly | Icon systems |
| `<object>` | No | Yes | Its own document | Rare, legacy |

## Accessible SVG

Meaningful graphics get **`role="img"`** plus a name: `aria-label`, or `aria-labelledby` pointing at a `<title>` (and `<desc>` for longer descriptions). Decorative icons next to text get **`aria-hidden="true"`**. `focusable="false"` was an IE fix. **Data visualisations** need a text alternative: a summary of the takeaway and the data as a table.

```html
<!-- Meaningful, standalone -->
<svg role="img" aria-labelledby="t1 d1" viewBox="0 0 120 40">
  <title id="t1">Sales, 2026</title>
  <desc id="d1">Sales rose steadily from 12 in January to 48 in June.</desc>
  <polyline points="0,36 24,30 48,26 72,18 96,10 120,4" fill="none" stroke="currentColor"/>
</svg>

<!-- Decorative, next to its label -->
<button><svg aria-hidden="true" width="16" height="16"><use href="#i-trash"/></svg> Delete</button>
```

<Try task="An icon-only 'close' button uses an inline SVG. Write two accessible versions: one naming the button, one naming the SVG. Which is better?">
  Better: name the button and hide the icon: `<button aria-label="Close"><svg aria-hidden="true">…</svg></button>` (or visually hidden text inside the button). Alternative: `<button><svg role="img" aria-label="Close">…</svg></button>`, which works because the button takes its name from content, but is more fragile. The name belongs to the control.
</Try>

## Optimising SVG

Exports from design tools carry editor metadata, ids, hidden layers, transforms and 6-decimal coordinates. Run **SVGO** (or SVGOMG in the browser), round precision to 1–2 decimals, remove metadata and empty groups, and **never remove `viewBox`** (without it the SVG can't scale). Export from Figma with "outline stroke" off unless you need fills, and flatten only what must be flattened.

```xml
<!-- Before: 612 bytes exported -->
<?xml version="1.0" encoding="UTF-8"?>
<svg width="24px" height="24px" viewBox="0 0 24 24" version="1.1" xmlns="http://www.w3.org/2000/svg" xmlns:xlink="http://www.w3.org/1999/xlink">
  <title>icon/check</title>
  <g id="Symbols" stroke="none" stroke-width="1" fill="none" fill-rule="evenodd">
    <g id="icon/check" transform="translate(-0.000000, 0.000000)" stroke="#000000" stroke-width="2">
      <polyline id="Path" points="4.00000 12.50000 9.00000 17.50000 20.00000 6.50000"></polyline>
    </g>
  </g>
</svg>

<!-- After: 118 bytes, theme-aware -->
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"><path d="M4 12.5l5 5 11-11"/></svg>
```

<Try task="Paste one exported SVG from any icon set into SVGOMG, compare the output with the original, and list which removals were safe and which (if any) changed the rendering.">
  Typical safe removals: XML prolog, editor namespaces and ids, empty groups, default attribute values, redundant transforms, excess precision. Watch out for: removing `viewBox` (breaks scaling), merging paths that were animated separately, removing ids referenced by CSS or `<use>`, and collapsing groups that carried a `transform` or `opacity`.
</Try>

## SVG animation

CSS transitions and animations work on SVG presentation properties (`fill`, `stroke`, `stroke-dashoffset`, `transform`, `opacity`). Set **`transform-box: fill-box`** so `transform-origin: center` means the shape's own centre. **SMIL** (`<animate>`, `<animateTransform>`, `<animateMotion>`) is legacy but still works everywhere and can animate path data and motion along a path. **Path morphing** needs matching command counts; libraries (Flubber, GSAP MorphSVG) handle the rest. Respect `prefers-reduced-motion`.

## Canvas 2D

`<canvas>` is an **immediate-mode bitmap**: you issue drawing commands (paths, fills, images, text, compositing) and the canvas keeps only pixels. For crisp output, size the backing store by **`devicePixelRatio`** and scale the context. `OffscreenCanvas` moves drawing into a worker. A canvas is an image to assistive technology: give it a label and provide its content elsewhere.

## Beyond: WebGL, shaders, WebGPU, Lottie and Rive

**WebGL** (and Three.js / React Three Fiber on top) draws 3D and runs **GLSL fragment shaders**: a small function executed for every pixel in parallel on the GPU, the basis of animated gradients, noise and generative backgrounds. **WebGPU** is the modern successor with compute shaders **[Frontier]**. **Lottie** plays After Effects exports; **Rive** plays interactive, state-machine-driven vector animation; Spline exports 3D scenes. Each costs bytes and main-thread time, so use them where they carry the idea, not as decoration.

## Choosing the medium

| Need | Medium |
| --- | --- |
| UI, text, forms, layout | HTML + CSS |
| Resolution-independent shapes, icons, charts up to a few thousand elements, anything you need to style, query or make accessible | SVG |
| Many thousands of moving objects, pixel manipulation, image processing | Canvas 2D (in a worker with OffscreenCanvas if heavy) |
| 3D, shaders, heavy particles, generative backgrounds | WebGL / WebGPU |
| Designer-authored vector animation with states | Rive or Lottie |
