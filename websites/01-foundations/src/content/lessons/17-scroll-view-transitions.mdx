## Scroll-driven animations

Replace the clock with scroll position: **`animation-timeline: scroll()`** follows a scroll container's progress; **`view()`** follows one element's journey through the scrollport. Name timelines with `scroll-timeline`/`view-timeline` and share them across the tree with `timeline-scope`. **`animation-range`** (`entry`, `exit`, `cover`, `contain`, with offsets) chooses which part of the journey drives the keyframes. They run on the compositor where possible and replace most scroll listeners and IntersectionObserver class toggles: reading-progress bars, reveals, parallax, sticky storytelling, image sequences, horizontal sections, shrinking headers. (The reading bar at the top of this page and the card reveals on the home page are scroll-driven.)

## Scroll snap

`scroll-snap-type` (`x`/`y`, `mandatory`/`proximity`) on the container, **`scroll-snap-align`** on children, `scroll-snap-stop: always` to stop flings skipping items, and **`scroll-padding`** / **`scroll-margin`** (also used so sticky headers don't cover anchor targets). Snap events `scrollsnapchange` and `scrollsnapchanging` **[Frontier]**. **Mandatory snapping becomes a trap** when content is taller or wider than the viewport: the browser snaps past what you need to read.

## CSS carousels **[Frontier]**

Carousels built on scroll containers get keyboard, touch and assistive-technology support for free. New pseudo-elements add controls: **`::scroll-marker`** on each item and **`scroll-marker-group`** on the container create dot navigation (styled with **`:target-current`**), and **`::scroll-button(left|right)`** creates previous/next buttons. The browser supplies the accessibility semantics (a tablist of markers, labelled buttons).

## Scrolling behaviour and the scroll-jacking critique

`scroll-behavior: smooth` (always behind `prefers-reduced-motion: no-preference`), `overscroll-behavior: contain` (no scroll chaining from modals and drawers), **scroll anchoring** (`overflow-anchor`: the browser keeps your place when content loads above), `scrollbar-gutter`, and scroll-state queries (Part 13). **Scroll-jacking** and smooth-scroll libraries (Lenis and friends) are beautiful on trackpads and hostile to keyboard, assistive-technology and low-power users unless handled carefully: they fight the platform's own physics.

## View Transitions

### Same-document

`document.startViewTransition(update)`: the browser snapshots the old state, runs your update, snapshots the new state, and animates between them. Give elements a **`view-transition-name`** for shared-element morphs (a thumbnail becoming a hero), `view-transition-class` to style groups, `match-element` for automatic names **[Frontier]**. Style the **pseudo-element tree** (`::view-transition`, `::view-transition-group(name)`, `::view-transition-image-pair()`, `::view-transition-old()`, `::view-transition-new()`) with normal CSS animations; use **transition types** for directional navigation and `:active-view-transition` for global styles during the transition. Respect reduced motion.

### Cross-document (multi-page)

Add **`@view-transition { navigation: auto; }`** to both pages. Same-origin navigations then animate with no JavaScript; the `pageswap` and `pagereveal` events customise them, and `<link rel="expect" blocking="render">` holds the first paint until key content arrives. **Multi-page sites get app-like transitions with zero framework**: navigate between lessons on this site to see the page fade out and rise in while the logo stays put.

### Pitfalls

Names must be **unique per snapshot**; aspect-ratio changes stretch images (set `object-fit` on the image pair); text distorts during morphs; long-running updates freeze the page (the old snapshot stays up); and you must manage focus and scroll after the swap.

## Beyond CSS: libraries, authored animation, shaders, text and pointer effects

- **GSAP** (timelines, ScrollTrigger, SplitText, Flip, MorphSVG; now free) is the creative-motion workhorse; **Motion** (formerly Framer Motion) for React layout animations and gestures; **Lenis** for smooth scroll; **Theatre.js** for authored timelines.
- **Designer-authored animation**: Lottie (After Effects → JSON) and **Rive** (interactive state machines), with their bundle and runtime costs.
- **3D and shaders**: Three.js / React Three Fiber, GLSL fragment shaders, post-processing, WebGPU **[Frontier]**, with obligations: pause, fallbacks, reduced motion, battery.
- **Text effects**: split-text animation is accessible only when the original text stays in the accessibility tree and the split spans are `aria-hidden`; kinetic type, variable-axis animation, scramble effects, marquees (with a pause).
- **Pointer-driven effects**: custom cursors, magnetic buttons, a spotlight following the pointer (a custom property updated on `pointermove`), tilt cards, and the touch and keyboard alternatives each needs.

## "Awwwards-level" craft, deconstructed

Award-winning sites usually combine: **strong typography**, **a grid**, **restrained colour**, **one signature interaction**, page transitions, scroll choreography, preloaders that earn their wait, and opt-in sound. Study them by slowing animations down (DevTools → Animations panel at 10%), reading their CSS and JavaScript, and tracing performance. And critique them: many are inaccessible, heavy and fragile. **Learn the craft and refuse the costs.**

<Try task="Pick one award-winning site. With the Animations panel at 10% speed and a Performance trace, write down: its signature interaction, how it's built (CSS, WAAPI, GSAP, WebGL), its JavaScript weight, and what happens with reduced motion and a keyboard.">
  A typical write-up: "Signature: a WebGL image distortion on hover (Three.js shader, ~600 KB JS). Page transitions via GSAP + a router. Scroll uses Lenis. Reduced motion: ignored, parallax still runs. Keyboard: the custom cursor hides focus, and the menu isn't reachable with Tab." Then redesign it: keep the signature distortion behind `prefers-reduced-motion: no-preference`, replace the router with cross-document view transitions, and drop Lenis.
</Try>

## Choosing the tool

CSS transitions → CSS animations → scroll-driven animations / view transitions → WAAPI → a motion library → canvas/WebGL. **Move right only when the step to the left genuinely can't do it.**

<Try task="Choose the lightest tool for: a button hover, a looping loading indicator, a header that shrinks on scroll, a list that animates reordering, a drag-to-dismiss sheet with velocity, and a 3D product turntable.">
  Hover: CSS transition. Loading indicator: CSS animation (paused under reduced motion). Shrinking header: scroll-driven animation (or a scroll-state query). Reordering list: view transition with `view-transition-name` per item, or FLIP with WAAPI. Drag-to-dismiss with velocity: a motion library (gestures and velocity hand-off) or hand-written pointer events with a spring. 3D turntable: WebGL (Three.js) with a static image fallback.
</Try>
