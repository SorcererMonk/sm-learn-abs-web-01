## Document anatomy

A minimal document is `<!doctype html>`, then `<html lang>`, `<head>` and `<body>`. The doctype is not decoration: it switches the browser into **standards mode**. Without it you get **quirks mode**, which emulates 1990s browsers (percentage heights resolve differently, tables don't inherit font sizes, the box model can change); certain old doctypes give **limited-quirks** mode (only the line-height quirk for images in table cells).

`<html>`, `<head>`, `<body>` and `<tbody>` tags, and closing `</p>` and `</li>` tags, are **optional**: the parser infers them. A document that omits them still gets them in the DOM.

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Minimal and complete</title>
  </head>
  <body>
    <p>Content.</p>
  </body>
</html>
```

<Try task="Open DevTools on any page and run `document.compatMode`. What does it return, and what would a page without a doctype return?">
  `"CSS1Compat"` means standards mode. A page without a doctype returns `"BackCompat"`, meaning quirks mode. Always start with `<!doctype html>`.
</Try>

## Syntax precisely

- **Elements vs tags**: `<p>` is a start tag, `</p>` an end tag, and the element is the node they produce.
- **Attributes** may be double-quoted, single-quoted or (without spaces and certain characters) unquoted. **Boolean attributes** are true when present: `disabled="false"` still disables.
- **Character references**: `&amp;`, `&lt;`, `&nbsp;`, `&#8212;`. Needed for `<` and `&` in text, and for quotes inside attribute values.
- **Void elements** have no content and no end tag: `img, input, br, meta, link, source, hr, wbr, area, col, embed, track, base`.
- **`<div />` is not self-closing.** On non-void elements the slash is ignored, so the div swallows everything after it.

## The parsing algorithm

The spec defines a **tokeniser** (a state machine over characters) and **tree construction** (insertion modes that decide where each token goes). Its famous recoveries:

- **Implied end tags**: `<p><div>` closes the `<p>`; a new `<li>` closes the previous one.
- **The adoption agency algorithm** repairs misnested formatting tags such as `<b><i></b></i>` by cloning elements.
- **Foster parenting** moves stray content inside `<table>` to *before* the table.
- **`<template>` content** is parsed into an inert document fragment: nothing runs or loads until you clone it.
- **Raw text elements** (`script`, `style`) and **escapable raw text** (`textarea`, `title`) are not parsed as markup at all.

This is why `innerHTML` can produce DOMs you didn't write: the same parser runs, with the same recoveries.

<ParserLab title="Recovery in action: foster parenting and the adoption agency" initial={'<table>Before<tr><td>cell</td></tr></table>\n<b>bold <i>both</b> italic?</i>'} />

<Try task="Predict the DOM for `<a href='/a'>one <a href='/b'>two</a></a>` and then check it in the museum.">
  Two sibling links: `<a href="/a">one </a><a href="/b">two</a>`. Interactive content can't nest in `<a>`, so the second `<a>` start tag closes the first (adoption agency), and the final `</a>` is ignored.

## The DOM that results

The DOM contains **element, text, comment, document and fragment nodes**. Whitespace between tags becomes **text nodes**, which is why inline-block items have gaps between them. **Attributes are not properties**: `value` the attribute is the *default*, `.value` the property is the *current* value; `class` the attribute is `className` the property. And every element with an `id` becomes a global variable on `window` (a historical feature: never rely on it).

## Encoding

Use **UTF-8, always**, and declare it with `<meta charset="utf-8">` **within the first 1024 bytes** (the browser's prescan looks no further). A byte-order mark also works. "Mojibake" (garbled characters such as `cafÃ©`) happens when bytes written as UTF-8 are decoded as something else, which is usually a server `Content-Type` header problem, not an HTML one.

## Global attributes you must know cold

`id`, `class`, `lang`, `dir`, `title` (a poor accessibility tool: invisible to touch and keyboard users), `hidden` (and `hidden="until-found"`, revealed by find-in-page), **`inert`** (removes a subtree from focus and the accessibility tree), `tabindex`, `contenteditable`, `draggable`, `spellcheck`, `translate`, `autofocus`, `inputmode`, `enterkeyhint`, `autocapitalize`, `popover`, `data-*` (read via `dataset`), `nonce`, `part`, `slot`, `accesskey` (avoid: conflicts with assistive-technology shortcuts) and `style` (rarely: it blocks strict CSP and fights the cascade).

## Scripts and styles in the document

`<script>` blocks parsing while it downloads and runs. **`defer`** downloads in parallel and runs after parsing, in order. **`async`** runs whenever it arrives. **`type="module"`** is deferred by default and supports **import maps**; `nomodule` is legacy. `blocking="render"` holds first paint for a critical script. `<link rel="stylesheet">` is render-blocking unless its `media` doesn't match (it still downloads, but doesn't block). `<noscript>` shows content when scripting is off. Put styles in the head, and scripts at the end of `<head>` with `defer`.

<ScriptTimeline />

```html
<head>
  <link rel="stylesheet" href="/app.css">
  <link rel="stylesheet" href="/print.css" media="print">
  <script type="importmap">{ "imports": { "lit": "/vendor/lit.js" } }</script>
  <script type="module" src="/app.js"></script>
</head>
```

## Validation and conformance

"Works in my browser", **valid** and **conforming** are different things. The **Nu HTML Checker** (validator.w3.org/nu) catches nesting errors, duplicate IDs, missing `alt`, invalid attributes, and interactive content inside `<a>` or `<button>`. Conformance matters because every consumer (parsers, crawlers, screen readers, your future self) sees the same predictable document.

<Try task="Paste this into validator.w3.org/nu and list every error: `<a href='/x'><button>Buy</button></a><img src='p.jpg'><p id='x'></p><p id='x'></p>`">
  (1) `button` must not appear as a descendant of `a` (interactive content can't nest). (2) `img` is missing an `alt` attribute. (3) Duplicate ID `x`. Also: no doctype, `<title>` or `lang` if checked as a whole document.
</Try>

## Writing HTML well

Indent consistently, keep a conventional attribute order (`class`/`id` first, then the element-specific attributes, then ARIA and `data-*`), one element per concern, meaningful class names that describe *what* rather than *how it looks*, and clean templates (Part 22).

```html
<!-- Before: presentational names, div soup -->
<div class="big-red-text" onclick="go()">Buy</div>

<!-- After: the element says what it is; the class says what it's for -->
<button class="cta" type="button">Buy</button>
```

<Try task="Rewrite `<div class='title-large'>Pricing</div><div class='link' onclick='goToPlans()'>See plans</div>` semantically.">
  `<h2 class="section-title">Pricing</h2><a class="cta" href="/plans">See plans</a>`. A heading is a heading (it joins the outline); navigation is a link (it works with middle-click, keyboard, crawlers and without JavaScript).
</Try>
