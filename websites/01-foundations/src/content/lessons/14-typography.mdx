## Why typography dominates

Most interfaces are mostly text. Type choice, size, spacing and measure decide readability, hierarchy and brand more than any other decision. "Web design is 95% typography" (Oliver Reichenstein) is an exaggeration worth taking seriously.

## Anatomy and vocabulary

**Baseline**, **x-height**, **cap height**, ascender, descender, counter, stroke contrast; classifications (serif, sans, slab, mono, display, script); optical sizes, weights and widths; **tracking** (spacing all letters) vs **kerning** (specific pairs); **leading** (line height); **measure** (line length); widows and orphans; rivers; ligatures; old-style vs lining vs **tabular** figures. CSS can measure several of these: `1ex` is the x-height and `1cap` the cap height of the current font.

## `@font-face` precisely

`src` needs only **woff2** now (with `format("woff2")` and optionally `tech()`); variable fonts declare **ranges** (`font-weight: 100 900`, `font-stretch: 75% 125%`). **`unicode-range`** makes the browser download a subset only when the page uses those characters. **`font-display`**: `swap` (show fallback, swap when ready: FOUT), `fallback` (short block, short swap window), `optional` (use it only if it's instantly available), `block` (invisible text: FOIT). The **metric overrides** `size-adjust`, `ascent-override`, `descent-override` and `line-gap-override` make a local fallback font occupy the same space as the web font: **zero-CLS font loading**. This site's fonts, simplified:

```css
@font-face {
  font-family: "Instrument Sans Variable";
  src: url(/fonts/instrument-sans-latin-wght.woff2) format("woff2");
  font-weight: 400 700;
  font-display: swap;
  unicode-range: U+0000-00FF, U+0131, U+0152-0153, U+2000-206F, U+20AC, U+2122;
}
/* A local font reshaped to match the web font's metrics, so the swap doesn't shift layout */
@font-face {
  font-family: "Instrument Sans Fallback";
  src: local("Arial"), local("Liberation Sans"), local("Helvetica");
  size-adjust: 102%;
  ascent-override: 95.1%;
  descent-override: 24.5%;
  line-gap-override: 0%;
}
body { font-family: "Instrument Sans Variable", "Instrument Sans Fallback", system-ui, sans-serif; }
```

<Try task="Open DevTools → Rendering → Layout Shift Regions, disable the cache and reload this page. Does anything flash when the fonts swap? Then remove the fallback face's overrides (in DevTools) and reload.">
  With the overrides, the swap from Arial/Liberation to Instrument Sans changes glyph shapes but not line breaks or heights, so no shift is reported. Without them, the fallback's different average width and ascent reflow the paragraphs: headings rewrap, and the Layout Shift Regions overlay flashes over most of the page.
</Try>

## Loading strategy

**Self-host**: browsers now partition the HTTP cache by site, so a third-party font CDN gives no cross-site cache benefit, costs a connection and leaks visitors to a third party. **Preload** only the one or two critical files, with `crossorigin`. **Subset** with `glyphhanger` or `pyftsubset` (and check the features survive). The **CSS Font Loading API** (`document.fonts.ready`, `document.fonts.load()`) lets scripts wait for fonts before measuring text. Budget: two families, few weights; one variable file often beats several statics.

```js
// Measure text only after the fonts it depends on have loaded
await document.fonts.load('600 1rem "Instrument Sans Variable"');
await document.fonts.ready;
const width = headline.getBoundingClientRect().width;

// Subset a font to Latin with the features you need (keeps tnum and liga)
// pyftsubset Font.ttf --unicodes="U+0000-00FF" --layout-features="kern,liga,tnum" --flavor=woff2
```

<Try task="Open the Network panel on a site that uses Google Fonts. How many requests and connections does the font setup cost before text renders, and what would self-hosting change?">
  Typically: one request to fonts.googleapis.com for CSS (render-blocking), then connections to fonts.gstatic.com for each woff2: two extra origins, DNS + TLS each, before text can render. Self-hosting removes the CSS hop and both connections, lets you preload the exact files, and keeps visitor IPs private.
</Try>

## Variable fonts

One file, continuous axes. **Registered axes** map to high-level properties: `wght` → `font-weight: 437`, `wdth` → `font-stretch`, `slnt`/`ital` → `font-style: oblique 10deg`/`italic`, `opsz` → `font-optical-sizing: auto`. **Custom axes** (uppercase tags like `GRAD` for grade without reflow, `CASL`, `SOFT`, `WONK`) go through `font-variation-settings`, which **doesn't inherit piecemeal**: setting one axis resets the others, so compose it from custom properties. Axes animate, for expressive typography (mind reduced motion).

## OpenType features

Prefer high-level properties: `font-variant-numeric` (`tabular-nums`, `lining-nums`, `oldstyle-nums`, `slashed-zero`, `diagonal-fractions`), `font-variant-ligatures`, `font-variant-caps` (`small-caps`, `all-small-caps`), `font-variant-alternates` with `@font-feature-values`, `font-variant-east-asian`, `font-kerning`, `font-variant-position`. Fall back to `font-feature-settings` (`"ss01"`, `"cv05"`, `"case"`, `"frac"`) for stylistic sets and character variants. **Tabular numbers in tables and counters** is the single most impactful feature.

## Synthesis, size-adjust and colour fonts

When a weight or style is missing, browsers **synthesise** faux bold (smeared strokes) and faux italic (slanted roman); `font-synthesis: none` forbids it. **`font-size-adjust`** scales fallbacks so their x-height matches the primary font (`font-size-adjust: ex-height 0.53` or `from-font`). **Colour fonts** (COLRv1) have palettes you can override with `@font-palette-values` and `font-palette`. Emoji render differently on every platform.

## Setting text

`font-size` in `rem` with a fluid scale (Part 13). A **modular scale** (1.2 minor third, 1.25 major third, 1.333 perfect fourth, 1.618 golden) gives steps a family resemblance; break it when the content asks. **Unitless `line-height`**: ≈1.4–1.6 for body, ≈1.05–1.2 for large headings (line height *decreases* as size increases). **Measure** 45–75 characters: `max-inline-size` somewhere around `55ch`–`65ch`, but measure it, because `1ch` is the width of "0" and most letters are narrower. Paragraph spacing *or* indentation, not both. `letter-spacing`: open up small caps and uppercase, tighten large display type slightly, never track lowercase body text.

## Line breaking and wrapping

**`text-wrap: balance`** (headings: even lines), **`text-wrap: pretty`** (paragraphs: no orphans, better rag), `text-wrap-mode` and `white-space-collapse` (the longhands of `white-space`: `nowrap`, `pre`, `pre-wrap`, `pre-line`, `break-spaces`). **`overflow-wrap: anywhere`/`break-word`** breaks long words only when needed; `word-break: break-all` breaks anywhere, `keep-all` keeps CJK words together. **`hyphens: auto`** needs a correct `lang` (`hyphenate-limit-chars` **[Frontier]**); `&shy;` and `<wbr>` suggest break points manually; `line-break: strict` for CJK.

## Truncation

Single line: `text-overflow: ellipsis` needs `overflow: hidden`, `white-space: nowrap` and a width. Multiple lines: **`line-clamp`** (still `-webkit-line-clamp` with `display: -webkit-box` in most engines). Truncated content must stay **accessible**: the full text available via the link target or a disclosure. A **fade-out mask** is a softer alternative.

## Vertical rhythm and trimming

Strict baseline grids are rarely worth it on the web; pragmatic rhythm is. The **`lh`** and **`rlh`** units (one line height of the element or the root) make spacing rhythmic: `margin-block: 1rlh`. **`text-box-trim`** with `text-box-edge: cap alphabetic` removes the extra space above caps and below the baseline, so text aligns optically with icons and box edges (leading trim) **[Frontier → Baseline-bound]**.

## Writing modes and international typography

`writing-mode: vertical-rl` for Japanese, Chinese and Mongolian; `text-orientation`; **`text-combine-upright`** (tate-chū-yoko: horizontal digits inside vertical text); bidirectional text with `dir`, `unicode-bidi` and `<bdi>`. **Never letter-space connected scripts** (Arabic, Devanagari: it breaks joins). Give scripts with tall stacks (Devanagari, Thai) more line height. **Noto** is the pan-script fallback.

## Typographic design: pairing and hierarchy

**Pairing**: contrast in one dimension (serif vs sans, or width) and harmony in the others (x-height, era, proportions); a **superfamily** (Source Serif + Sans, IBM Plex) is the safe choice. **Hierarchy with the fewest variables**: size, weight, colour, case and space; change one or two per level. Type as brand; display faces vs text faces; reading typography (long, calm) vs interface typography (short, dense, scannable). The canon: *The Elements of Typographic Style* (Bringhurst), *Thinking with Type* (Lupton), *Practical Typography* (Butterick).

## Sourcing type

**Google Fonts** and **Fontsource** (npm packages for self-hosting; this site uses it), **Fontshare**, foundries and **licensing** (desktop vs web licences, pageview limits, app embedding). Open-source families worth knowing: Inter, Source Serif/Sans, IBM Plex, Literata, **Fraunces** and **Instrument Sans** (this site), Recursive, Atkinson Hyperlegible.

<Try task="For a paid font you like, find its web licence terms: is it priced by pageviews, domains or company size? What happens if your site goes viral? Then name an open-source alternative with similar character.">
  Many foundries license webfonts by monthly pageviews (e.g. up to 10k, 100k, 1M) and per domain; exceeding tiers means buying up, and apps or PDFs need separate licences. Open-source (SIL OFL) fonts avoid all of that: Inter or Instrument Sans for neutral grotesques, Fraunces or Literata for characterful serifs, IBM Plex for a superfamily with mono.
</Try>
