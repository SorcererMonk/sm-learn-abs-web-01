## The division of labour

**HTML holds structure and state** (attributes like `open`, `aria-expanded`, `hidden`, `data-state`), **CSS reacts** to that state with selectors, and **JavaScript only changes state**. Toggling an attribute, not writing inline styles, keeps the three languages honest: the state is inspectable, accessible and styleable.

## DOM essentials for styling

`querySelector(All)`; `classList.toggle(name, force)`; `dataset`; `setAttribute`/`toggleAttribute`; **`element.style.setProperty('--x', value)`** to pass values (pointer position, scroll progress, measured sizes) into CSS; `getComputedStyle`; `getBoundingClientRect()` (and its layout cost); and **`matchMedia`** with change listeners for media queries in JavaScript.

## Observers

The modern replacement for scroll and resize listeners: **`IntersectionObserver`** (lazy loading, reveal animations, active-section navigation), **`ResizeObserver`** (component sizes, now mostly replaced by container queries), and **`MutationObserver`** (react to DOM changes). They're batched and asynchronous, so they don't force layout on every scroll event.

## Events relevant to UI

**Pointer events** unify mouse, touch and pen (`pointerdown`, `pointermove`, `pointerup`, `setPointerCapture`); CSS `pointer-events: none` and **`touch-action`** (which gestures the browser handles). Keyboard events and `key` values; focus events (`focusin`/`focusout` bubble); `transitionend`/`animationend`; **`toggle`/`beforetoggle`** for popovers and details; `command` events **[Frontier]**; and **passive listeners** for scroll and touch.

## CSS object APIs

## Web components

**Custom elements** (`customElements.define`, lifecycle callbacks, `observedAttributes`), **shadow DOM** (`attachShadow`, open vs closed, style encapsulation both ways), **`<slot>`** and named slots, **Declarative Shadow DOM** (`<template shadowrootmode="open">`) for server rendering without JavaScript. Styling across the boundary: inherited and custom properties pass in; **`::part()`** exposes internals; `::slotted()` styles light-DOM children one level deep; `:host`/`:host()` style the element itself; `exportparts`. Use **`:defined`** to avoid flashes of unstyled components, **`ElementInternals`** for form participation and default ARIA, custom states with **`:state()`**, and scoped custom element registries **[Frontier]**.

## When web components win, and when they're awkward

They **win** for design systems shared across frameworks, long-lived widgets embedded in unknown pages (third-party embeds), and **"HTML web components"** that wrap and enhance existing markup instead of rendering it. They're **awkward** for SSR-heavy apps without Declarative Shadow DOM, for accessibility across shadow boundaries (ID references like `aria-labelledby` can't cross them yet; reference target is **[Frontier]**), and for the boilerplate of form participation.

## Progressive enhancement

The HTML works first: links navigate, forms submit, details open. JavaScript upgrades it: fetch instead of a full reload, richer widgets. Feature-detect instead of sniffing browsers. `<noscript>` is rarely needed when the baseline already works.

## Framework literacy for markup authors

JSX and templates compile to DOM operations. Frameworks warn about **keys** because list identity decides whether elements are moved or recreated (focus and state follow). **`dangerouslySetInnerHTML`** is an XSS risk (Part 25). **Hydration mismatches** come from markup that differs between server and client: dates and times, random IDs, `typeof window` branches, and **invalid nesting the parser rewrites**.

```tsx
// Hydration mismatch: the parser moves the <div> out of the <p> on the server HTML
export function Price({ amount }: { amount: number }) {
  return (
    <p>
      Total: <div className="big">{amount}</div>   {/* invalid: <div> in <p> */}
    </p>
  );
}

// Also mismatches: different output on server and client
const id = Math.random().toString(36);           // use React's useId() instead
const now = new Date().toLocaleTimeString();     // render on the client, or pass the server time down
```

<Try task="View source on a React or Vue app and compare it with the Elements panel after load. Find one place where the parser or hydration changed the DOM (hint: search the source for a <div> or <p> inside a <p>, or a <tr> directly in a <table>).">
  The server HTML text is parsed by the browser's HTML parser, which fixes invalid nesting: `<p>…<div>` closes the paragraph early, and `<table><tr>` gets a `<tbody>` inserted. The DOM no longer matches the framework's expected tree, so hydration warns ("did not match") and may re-render. The fix is valid nesting: `<span>` inside `<p>`, explicit `<tbody>`.
</Try>
