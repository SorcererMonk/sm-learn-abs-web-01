## Anatomy: rules, declarations and shorthands

A **rule** is a selector plus a **declaration block**; each **declaration** is a property and a value; **at-rules** (`@media`, `@layer`…) wrap or configure rules. **Shorthands** set every longhand they cover, including the ones you didn't mention: `background: red` resets `background-size` and `background-image`; `font: 16px serif` resets `line-height` to `normal`. And **invalid declarations are dropped individually**, which is the basis of fallback by repetition: write the safe value first, the modern one second.

## The cascade, in order

For each property on each element, the browser gathers every declaration that applies and sorts them:

1. **Origin and importance**: user-agent → user → author for normal declarations, *reversed* for `!important`; animations and transitions have their own positions (transitions beat everything).
2. **Context**: shadow DOM encapsulation (outer-context normal styles beat inner; `!important` reverses).
3. **Element-attached styles**: the `style` attribute.
4. **Cascade layers**.
5. **Specificity**.
6. **Scope proximity** (`@scope`).
7. **Order of appearance**.

Most people only know steps 5 and 7, and that's why CSS feels arbitrary to them.

## Specificity, exactly

Specificity is a triple **(ID, CLASS, TYPE)** compared column by column. Attribute selectors and pseudo-classes count as classes; pseudo-elements as types; `*` and combinators count zero. **`:is()`, `:not()` and `:has()` take their most specific argument**; **`:where()` is always zero**, which makes it the tool for overridable defaults. Inline styles sit above all selectors (step 3), `!important` jumps origins (step 1) rather than adding specificity, and nesting behaves like `:is()`.

## Cascade layers

Declare the order once, up front: **`@layer reset, base, components, utilities;`**. Later layers beat earlier ones regardless of specificity. Anonymous layers (`@layer { … }`) can't be added to later; nested layers are addressed as `framework.base`; **`@import url(vendor.css) layer(vendor)`** puts third-party CSS in a low layer. **Unlayered styles beat all layered styles** for normal declarations; `!important` **reverses** layer order, so a reset can protect itself. `revert-layer` rolls a property back to the previous layer. This site uses `@layer reset, tokens, base, layout, components, motion, site, demos, print`.

## Inheritance and the explicit keywords

Mostly **text properties inherit**: `color`, `font-*`, `line-height`, `letter-spacing`, `text-align`, `visibility`, `cursor`, and all custom properties. **Box properties don't**: margins, padding, borders, backgrounds, sizing, layout. The keywords: **`inherit`** (take the parent's), **`initial`** (the *spec* initial value: `display: initial` is `inline`), **`unset`** (inherit if inherited, else initial), **`revert`** (back to the user-agent style), **`revert-layer`** (back to the previous layer). `all: unset` or `all: revert` resets a component in one line.

## The value pipeline

Each value passes through stages: **declared** (everything that applies) → **cascaded** (the winner) → **specified** (winner or default) → **computed** (relative units resolved where possible, keywords resolved; this is what inherits) → **used** (after layout: percentages against real sizes) → **actual** (rounded to device pixels). `getComputedStyle()` returns *resolved* values: a historical mix of computed and used.

## Units

- **Absolute**: `px` is the *reference pixel* (1/96 inch at arm's length), not a device pixel.
- **Font-relative**: `em` (compounds through nesting), `rem` (root), `ch` (width of "0"), `ex`, `cap`, `ic`, `lh`, `rlh`.
- **Viewport**: `vw`/`vh`, and the mobile-address-bar-aware **`svh`** (small), **`lvh`** (large), **`dvh`** (dynamic); `vi`/`vb` (logical); `vmin`/`vmax`.
- **Container units**: `cqi`, `cqb`, `cqw`, `cqh`, `cqmin`, `cqmax` (Part 13).
- **Percentages** resolve against something different per property: **padding and margin use the containing block's width, even vertically**.
- `fr` (grid), angles (`deg`, `turn`, `rad`), time (`s`, `ms`), resolution (`dppx`, `x`).

## Math and functions

`calc()` mixes units (spaces are required around `+` and `-`). **`min()`, `max()` and `clamp(min, preferred, max)`** make values responsive without media queries. `round()`, `mod()`, `rem()` step values; `abs()`, `sign()`; **trigonometry** (`sin()`, `cos()`, `atan2()`) places items on a circle; `pow()`, `sqrt()`, `hypot()`, `log()`, `exp()` build modular type scales in pure CSS. Also `var()`, `env()` (safe-area and keyboard insets), typed **`attr()`**, `progress()`, `sibling-index()`/`sibling-count()` for staggering, and `calc-size()` **[Frontier]**.

## Custom properties in depth

Custom properties are **cascaded and inherited** like any property, resolved at computed-value time, and **scoped to the element tree**: set them on a component and its children see them. `var(--x, fallback)` uses the fallback when `--x` is the **guaranteed-invalid value** (unset). If a `var()` substitution produces an invalid value, the property becomes **invalid at computed-value time** and behaves as `unset`; it does *not* fall back to an earlier declaration. Use them as **component APIs** (`--button-bg`), theme hooks and runtime switches (`style.setProperty('--x', …)`). Changing one on `:root` restyles everything that uses it.

## `@property`: typed, animatable custom properties

Registering a property with **`syntax`** (`<length>`, `<color>`, `<angle>`, `<percentage>`, `<number>`, `*`), **`inherits`** and **`initial-value`** makes it type-checked (invalid values fall back to the initial value), **animatable and interpolable** (animated gradients, conic progress rings), and optionally non-inheriting (a performance win in deep trees).

## Resets and defaults

Browsers ship a **user-agent stylesheet** (read Chromium's `html.css` once). normalize.css made browsers consistent; a **modern reset** fixes the defaults that cause bugs: `box-sizing: border-box` for everything, deliberate margins, `img { display: block; max-width: 100% }`, form controls inheriting fonts, `text-wrap: pretty` on paragraphs, and reduced-motion defaults. It lives in the **lowest layer** so everything overrides it. This site's reset, abridged:

```css
@layer reset {
  *, *::before, *::after { box-sizing: border-box; }      /* widths include padding and border */
  * { margin: 0; }                                         /* spacing is set deliberately, by layout */
  html { -webkit-text-size-adjust: none; text-size-adjust: none; } /* no surprise font inflation on iOS */
  body { min-block-size: 100svh; line-height: 1.5; }       /* readable default leading */
  img, picture, video, canvas, svg { display: block; max-inline-size: 100%; } /* no inline gaps, no overflow */
  input, button, textarea, select { font: inherit; }       /* form controls use the page font */
  p, li, figcaption { text-wrap: pretty; }                 /* fewer orphans */
  h1, h2, h3, h4 { text-wrap: balance; }                   /* balanced headlines */
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; }
  }
}
```

<Try task="Pick one line of the reset above, delete it from a page you built, and describe the bug that appears.">
  Without `box-sizing: border-box`, a `width: 100%` input with padding overflows its container. Without `img { display: block }`, images sit on the text baseline with a few pixels of gap below. Without `font: inherit` on controls, buttons and inputs use the system font at 13.33px. Without `min-block-size` on body, a short page's footer floats mid-screen.
</Try>
