## Process architecture

A modern browser is several cooperating processes:

- **Browser process**: UI, navigation, permissions, the network service and storage.
- **Renderer processes**, one per *site*: **site isolation** since Spectre means `evil.example` and `bank.example` never share one.
- **GPU process**: raster and compositing.
- **Utility processes**: audio, decoding, and others.

A renderer is sandboxed: it can't open files or sockets, and asks the browser process for everything, so a crashed tab doesn't take the browser down. Spectre-class attacks can read memory inside a process, so cross-origin data must never share a process. Timers are coarsened, and **`SharedArrayBuffer`** (a high-resolution timer in disguise) is only available when a page opts into **cross-origin isolation**:

- `Cross-Origin-Opener-Policy: same-origin` keeps other origins' windows out of its browsing context group.
- `Cross-Origin-Embedder-Policy: require-corp` refuses cross-origin subresources that haven't opted in.

## The navigation and loading sequence

End to end:

1. **URL parsing**, then **DNS**, then **connection setup** (TCP + TLS, or QUIC for HTTP/3).
2. The **HTML streams in** while the **preload scanner** races ahead of the parser, fetching scripts, stylesheets and images it can see in the markup.
3. **Tokenisation and DOM construction** pause at every classic `<script>` (parser-blocking). `async` and `defer` scripts don't pause it.
4. **CSSOM construction**. CSS is **render-blocking**: nothing paints until head stylesheets arrive.
5. Then the **render tree**, **layout**, **paint** and **compositing**.

## The main thread and the event loop

One main thread runs **tasks** (a script, a timer, an event handler). After each task the **microtask queue** is drained completely: promise reactions and `queueMicrotask`. Then the browser may take a **rendering opportunity**, running `requestAnimationFrame` callbacks, then style, layout and paint. **`requestIdleCallback`** runs only when a frame has time left.

A **long task** (more than 50 ms) delays everything behind it, including the response to a click: **input delay**, the first part of INP. The modern answer is to **yield**. `scheduler.yield()` (or `setTimeout(0)` as a fallback) splits work so input gets a turn, and `scheduler.postTask` sets priorities. `isInputPending` is the older, narrower tool. The rule: everything competes for one thread.

## Rendering pipeline internals

The pipeline runs in stages:

1. **Style recalculation**: which rules apply to which elements.
2. **Layout** (reflow): geometry. It is triggered by changing width, height, position, fonts or content, and forced *synchronously* when you read `offsetWidth`, `getBoundingClientRect()` or `scrollTop` after a write. Interleaving reads and writes in a loop is **layout thrashing**.
3. **Paint and raster**: turning boxes into pixels, per layer.
4. **Compositing**: on the **compositor thread**, which can move, scale and fade existing layers without the main thread. That is why `transform` and `opacity` animate smoothly while other properties don't.

`will-change` promotes an element to its own layer, so use it sparingly: every layer costs memory. `content-visibility: auto` and CSS **containment** (`contain: layout paint`) tell the browser it can skip work for offscreen or self-contained subtrees.

## The JavaScript engine

At the level an engineer needs (language mechanics are in `L1-coding-typescript-javascript.md`):

- **Parse and lazy compilation**: functions are pre-parsed and fully compiled on first call.
- **Bytecode**: executed by an interpreter.
- **An optimising JIT**: compiles hot functions using type feedback, and **deoptimises** when the assumptions break.
- **Hidden classes (shapes) and inline caches**: objects built the same way share a shape, and property access at a call site stays fast while it sees few shapes. Monomorphic is fast; megamorphic is a slow lookup.
- **Garbage collection**: generational (most objects die young), incremental and concurrent to shorten pauses.
- **Memory retention**, which is where leaks come from:
  - detached DOM nodes still referenced from JavaScript;
  - closures capturing large objects;
  - listeners and timers never removed;
  - caches that only grow.

## Threads off the main thread

**Web Workers** run JavaScript on their own thread and talk to the page with `postMessage`. Data is copied by **structured clone** unless you **transfer** it: transferring an `ArrayBuffer` moves ownership in constant time. **`SharedArrayBuffer`** gives true shared memory with `Atomics`, but only with cross-origin isolation. **Worklets** are tiny specialised threads (CSS paint, audio, animation).

Move off-thread what doesn't need the DOM:

- parsing large JSON or CSV;
- image and media decoding;
- crypto and compression;
- search indexes;
- heavy data transforms.

The DOM itself can only be touched from the main thread.

## Storage and quota

The main stores:

- **Cookies**: small, sent with every request.
- **`localStorage`**: synchronous. Every read and write blocks the main thread, so it's for tiny preferences only.
- **`sessionStorage`**: per tab.
- **IndexedDB**: async and transactional; the real client database.
- **The Cache API**: Request/Response pairs, used by service workers.
- **The Origin Private File System**: fast file access, with sync handles in workers.

All of them share an origin **quota**, managed by **StorageManager** (`estimate()`, `persist()`). Best-effort data can be **evicted** under pressure. Storage is **partitioned by top-level site**, so an embedded third party gets a separate jar on every site that embeds it.

## The browser's other engines

The browser has other engines you will meet:

- **The HTTP cache**: Parts 5 and 9.
- **The back/forward cache (bfcache)**: freezes whole pages in memory so Back is instant. It is disqualified by `unload` listeners, sometimes `no-store`, and open connections.
- **Prerendering and speculation rules**: `<script type="speculationrules">` lets you prerender likely next pages.
- **The HTML parser's error recovery**: every input produces a DOM, even broken markup.
- **Layout quirks across browsers**: a missing doctype triggers quirks mode, and engines still differ at the edges, which is what the Interop project tracks.
