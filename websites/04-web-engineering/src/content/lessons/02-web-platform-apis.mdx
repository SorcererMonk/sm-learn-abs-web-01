## HTML as semantics, not markup soup

HTML carries meaning, and each element brings behaviour for free:

- **Document structure**: landmarks (`header`, `nav`, `main`, `aside`, `footer`), headings as an outline, lists as lists, tables with real headers.
- **Actions and navigation**: `<button>` versus a clickable `<div>` (focus, keyboard, role, form participation come free with the former); links for navigation, buttons for actions.
- **Built-in widgets**: `<dialog>` (modal focus handling and `Esc`), `<details>`, and the **`popover`** attribute (top layer, light dismiss).
- **Forms**: `<form>` with native validation; **input types** that drive mobile keyboards and pickers; **`autocomplete` tokens** that drive autofill.
- **Media**: images with `alt`, `<picture>` and responsive images, `<video>` and `<audio>`.
- **`<template>`**, and metadata in `<head>`.

## Forms as a full platform feature

A form is a complete client–server protocol:

- **Submission with and without JavaScript**: `action`, `method` and named fields.
- **`FormData`** to read it all in one line.
- **Native validation**: `required`, `type`, `min`/`max`, `pattern`, with messages and `:user-invalid` styling.
- **Progressive enhancement**: the same form submitted with `fetch` when JavaScript is available.
- **Harder cases**: multi-step flows, and file inputs with `accept` and `multiple`.

Native form semantics are the difference between accessible and not: labels, fieldsets, error association and autofill all hang off real form controls.

## The DOM and events

The DOM is a tree of nodes (elements, text, comments) you traverse with `closest`, `querySelector` and `children`. **Mutation has a cost**: batch it with a `DocumentFragment` or `replaceChildren`.

**Events flow** in three phases: **capture** (window down to the target), **target**, then **bubble** back up. That is what makes **delegation** work: one listener on a list instead of one per item.

The rest of the event toolbox:

- **`{ passive: true }`** tells the browser a touch or wheel handler won't call `preventDefault`, so scrolling doesn't wait for it.
- **`AbortController`** removes many listeners (and cancels fetches) with one `abort()`.
- **`CustomEvent`** lets components announce things.
- **`MutationObserver`** watches the tree.
- **`IntersectionObserver`** drives lazy loading, analytics impressions and infinite scroll without scroll listeners.
- **`ResizeObserver`** watches element sizes.

## CSS from an engineering perspective

The engineering side of CSS:

- **The cascade and specificity**, tamed with **`@layer`**, plus inheritance.
- **Custom properties** as a runtime API: JavaScript and media queries can change a single value that everything reads.
- **Layout algorithms**: the box model, normal flow, flexbox, grid and subgrid.
- **Stacking contexts** and z-index.
- **Logical properties** (`margin-inline-start`) for right-to-left languages.
- **Container queries** and **`:has()`**.
- **Media queries** for preferences: `prefers-reduced-motion`, `prefers-color-scheme`, `forced-colors`.
- **Containment** and `content-visibility` as rendering-cost controls.
- **Transitions, animations and view transitions**, each with a performance profile (Part 1: only `transform` and `opacity` skip layout and paint).

## Web components and the shadow DOM

The pieces:

- **Custom elements**: a class registered with `customElements.define`.
- **Shadow roots**: encapsulated DOM and styles.
- **Slots**: the light DOM projected into the shadow tree.
- **Declarative shadow DOM**: `<template shadowrootmode>` renders on the server with no JavaScript.
- **Styling across the boundary**: `::part()`, `::slotted()`, and custom properties, which inherit through it.
- **Form participation**: `ElementInternals` with `static formAssociated = true`.

The honest assessment: they beat a framework for **design systems consumed by several frameworks** and **long-lived widgets**. For application state, rendering lists and routing, frameworks still carry more.

## Networking APIs

The client's networking toolbox:

- **`fetch`**: requests and responses, bodies as **streams**, cancellation with `AbortSignal` (and `AbortSignal.timeout(ms)`), `credentials` modes (`omit`, `same-origin`, `include`), and `keepalive` so a request can outlive the page.
- **Streams**: readable, writable and transform streams, the basis of streaming SSR and progressive rendering.
- **`WebSocket`**: two-way.
- **Server-Sent Events** (`EventSource`): one-way, with auto-reconnect.
- **`WebTransport`** **[Frontier]**: datagrams and streams over HTTP/3.
- **`navigator.sendBeacon`**: fire-and-forget analytics on page hide. This site's RUM uses it.

Choosing between polling, SSE and sockets is a design decision; Part 4 builds all three.

## Service workers and the Cache API

A service worker is a script the browser runs between your pages and the network, for its **scope**.

- **Lifecycle**: `install` (precache), `activate` (clean up, `clients.claim()`), then `fetch` interception. A new version **waits** until old tabs close, unless it calls `skipWaiting()`.
- **Caching strategies**: cache-first, network-first, stale-while-revalidate, and cache-then-network. **Precaching** is at install; **runtime caching** is on demand.
- **Update semantics**: the "stuck on an old version" failure comes from unversioned caches, a cached `sw.js`, or never prompting.
- **Debugging**: DevTools → Application → Service Workers, with "Update on reload" and "Bypass for network".

The lab below is a real app with a real worker, and a server you can deploy to or switch off:

```js
// The heart of stale-while-revalidate (from this lab's sw.js)
const cached = await cache.match(request);
const refresh = fetch(request).then(async (response) => {
  if (response.ok) await cache.put(request, response.clone());
  return response;
});
if (cached) { event.waitUntil(refresh); return cached; }  // instant, refreshed for next time
return refresh;                                              // first visit: wait for the network
```

## Device and capability APIs

The capability APIs include:

- geolocation;
- permissions, notifications and push;
- **Web Share**;
- the async **clipboard**;
- media capture;
- **Web Bluetooth, USB and Serial** **[Frontier]**, Chromium only;
- **Screen Wake Lock**;
- the **visual viewport**.

The **Permissions API** is the pattern for all of them: query the state, feature-detect, ask only in response to a user gesture, and design the "denied" and "unsupported" paths. **`Permissions-Policy`** decides what a document (and its iframes) may even ask for.

## Computation and graphics

For computation and graphics, the platform offers:

- **WebAssembly**: a compact bytecode that runs near native speed. It wins for ported C, C++ and Rust code (codecs, SQLite, physics), SIMD-heavy maths and predictable performance. It doesn't win for code the JIT already optimises: crossing the JS boundary has a cost, and threads need cross-origin isolation.
- **Canvas 2D** and **WebGL**.
- **WebGPU** **[Frontier]**: compute shaders and modern GPU access.
- **OffscreenCanvas**: rendering from a worker.
- **Web Audio** and **WebCodecs**: frame-level media.

## Security and identity APIs

- **Web Crypto** (`crypto.subtle`): digests, HMAC, AES-GCM, ECDSA and key derivation, native and constant-time. Never ship a JavaScript crypto library for these.
- **WebAuthn/passkeys**: public-key credentials bound to the origin, so phishing can't replay them (Parts 4 and 7 build the server side).
- **Credential Management**: stored credentials and federated sign-in.
- **Trusted Types**: typed DOM sinks, so strings can't reach `innerHTML` unvetted (Part 7).

## How the platform evolves

How features arrive:

- **WHATWG living standards**: HTML, DOM, Fetch, URL.
- **W3C specs**: CSS, WCAG and more.
- **TC39 stages 0–4** for JavaScript.
- **Standards positions**: published by Mozilla and WebKit.
- **Origin trials**: early features on real sites.

**Baseline** is the practical shipping signal: *newly available* when a feature works in all core browsers, and *widely available* 30 months later. Ship with **feature detection** (`CSS.supports`, `'x' in obj`, `@supports`), never user-agent sniffing. Polyfill only when the cost (bytes and maintenance) is worth it, and remove polyfills on a schedule.
